# BGNT IT 요청·이슈 통합 관리 시스템

현업 요청 접수부터 처리 현황, 완료 증빙, 시스템 이슈, 경영진 보고까지 연결한 사내 웹 시스템입니다.

## 문제와 역할

메일·메신저·종이 요청서·PDF로 분산된 요청은 중복이나 누락을 확인하기 어려웠고, 완료 문서와 원래 요청의 연결도 부족했습니다. 현업 절차에서 요구사항을 도출하고 데이터 구조·웹 화면·Python API·문서 분석 흐름을 설계했습니다. ChatGPT/Codex를 활용해 구현하고, 원본 문서 대조와 사용자 확인으로 결과를 검증했습니다.

## 구현

- 요청 CRUD, 대기·진행·완료 상태, 원본·완료 증빙 연결
- PDF 요청서 분석, 기존 요청 매칭, 불확실한 항목의 확인 필요 처리
- 관리자·조회 사용자 권한, 변경 이력, 동시 수정 충돌 확인, DB 백업
- 한·영 UI, 조건별 통계, 한·영 PDF 정기 보고서
- 여러 요청을 하나의 시스템 이슈에 연결하고 검증 근거·확인일을 별도로 관리

```mermaid
flowchart LR
 A[요청서·완료 증빙] --> B[업로드·문서 분석]
 B --> C[원본 대조·사용자 확인]
 C --> D[요청·처리 이력]
 D --> E[시스템 이슈]
 D --> F[통계·한영 보고서]
 E --> F
```

## 대용량 PDF 분석 오류 개선

여러 완료 요청서를 묶은 PDF가 분석 입력량 제한으로 중단됐습니다. 한 번에 전달하던 문서를 **최대 20페이지 단위**로 나누고, 구간 사이에 **2페이지 중첩**을 적용했습니다. 원본 페이지 번호와 요청번호를 대조해 이어지는 요청서·증빙을 연결하고, 누락·중복 검증과 체크포인트를 추가했습니다.

운영 DB와 분리한 환경에서 **80페이지 테스트 PDF**를 사용했습니다. 18–23페이지의 요청을 하나로 유지해 총 **75개 요청 그룹**이 만들어지는지, 재실행 중복 방지와 원본 SHA-256 보존을 확인했습니다. 관련 자동 테스트 2개가 통과했습니다. 이 결과는 **AI 응답을 모의한 분할·연결·저장 로직 검증**입니다.

## 통계 기준 개선

현재 완료 상태와 선택 기간 내 완료 실적이 다르게 표시되는 문제를 분석했습니다. 접수일·완료일 기준을 분리하고 완료일 미상·기간 밖 완료·이월 완료를 구분해 요약 카드, 상세 목록, 추이 그래프의 집계 범위를 맞췄습니다.

## 기술

| 영역 | 구성 |
| :--- | :--- |
| 화면 | HTML · CSS · Vanilla JavaScript |
| 서버·데이터 | Python `ThreadingHTTPServer` · `BaseHTTPRequestHandler` · SQLite |
| 문서·보고서 | pypdf · pypdfium2 · Pillow · ReportLab |
| AI 연결 | 로그인된 ChatGPT 계정을 사용하는 로컬 Codex App Server |
| 조회 도구 | FastMCP 기반 로컬 데이터·문서 연결 |
| 실행 | Windows 로컬 서버 · 허용된 사내 LAN |

실제 현업 요청서와 완료본을 관리하고 IT 대응 현황 보고에 활용했습니다. 요청 처리 완료와 시스템 근본 문제 해결을 구분하는 설계가 핵심입니다.
